# “我的长理”产品路线图（2026）

本文只记录已确认的开发顺序和正式业务边界，不代表相关后端、支付或校方能力已经接入。

## 阶段 0B：产品收敛

- 正式导航只保留：首页、服务、我的。
- 校园频道、普通发帖、搭子社、校园活动和校巴停止开发并从正式入口下线。
- 失物招领迁移为生活模块下的独立工具。
- 体育预约保留本地原型，用于验证场地、时段、预约、取消和状态恢复体验。
- 记账本、校园地图从正式用户入口移除；底层代码和既有本地数据暂不删除，便于安全回退。

## 阶段 1：基础后端

- 先完成后端技术方案、数据模型、数据库、账号体系与基础 API 契约。
- 第一批真实数据能力只接入失物招领和体育场地预约。
- 不把教务密码、Cookie 或现有教务认证凭据上传到自建服务。

## 阶段 2：管理后台

- 管理场地、场地编号、开放日期、时间段和库存。
- 管理预约、取消和异常订单。
- 管理失物信息及必要的审核、隐藏和状态流转。
- 管理公告、最低可用版本和版本更新信息。

## 阶段 3：校方规则与支付闭环

- 在取得校方授权并确认场馆规则后接入真实库存和预约规则。
- 接入微信支付、支付宝支付及服务端支付回调。
- 生成一次性或限时预约码。
- 提供场馆端扫码核验、入场确认和防重复核销。

正式场地预约闭环：

```text
学生选择场地和时段
-> 服务端锁定库存并生成待支付订单
-> 跳转微信或支付宝完成支付
-> 服务端确认支付结果
-> 生成一次性或限时预约码
-> 学生到场出示预约码
-> 场馆工作人员扫码核验
-> 系统确认入场 / 防止重复核销
```

服务端必须负责库存事务、锁超时释放、支付幂等、回调验签、订单状态机、预约码签发与核销原子性。客户端不能自行判定支付成功或最终库存。

## 阶段 4：发布准备

- 真实服务完整验收后，才能移除“本地 / 模拟 / 测试”文案。
- 使用独立 Release 签名生成候选包。
- 完成灰度测试、监控、回滚预案、隐私合规和商店材料。
- 正式上线前必须确认第三方 AAR 再分发授权、校名校徽授权、支付商户资质和校方场馆合作授权。

## 当前禁止误导

在阶段 3 的真实服务、支付和核验链路通过验收前：

- 不得把本地预约描述为真实订场；
- 不得显示虚假的支付成功、官方订单或预约码；
- 不得承诺场馆、价格、开放时间或库存真实有效；
- 不得移除本地模拟提示。
